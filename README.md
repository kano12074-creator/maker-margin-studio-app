# Maker Margin Studio — 商品原価・利益シミュレーター

食品メーカー、小規模菓子製造業、個人の食品ブランド向けのツールです。原価や販売価格を入力すると、以下をブラウザ内で計算します。

- 原価構成
- 粗利・粗利率
- 限界利益
- 損益分岐点
- 販売価格ごとの比較

- バックエンド・外部API・ビルド工程・npm 依存はありません（HTML / CSS / JavaScript のみ）。
- 入力データを外部へ送信しません。自動保存もしません（localStorage・Cookie も使いません）。
- GitHub Pages でそのまま公開できます。

> 本ツールは入力値に基づいて試算するものです。税務・会計上の最終判断を自動化するものではありません。

---

## 1. ファイル構成と設計

```
index.html            画面（A〜H の入力セクション＋計算結果）
styles.css            スタイル（白基調・深いグリーン／チャコール、レスポンシブ）
calc.js               計算ロジック（DOM 非依存。ブラウザでは window.MarginCalc、Node では require）
app.js                画面制御（入力の読み取り → calc.js で検証・計算 → 描画、CSV ダウンロード）
tests/calc.test.js    計算ロジックの単体テスト（node:test、依存なし）
tests/e2e.test.js     ブラウザ E2E テスト（Playwright。未導入なら自動スキップ）
tests/MANUAL_TEST.md  手動テスト手順
docs/EXAMPLES.md      使用例とサンプルデータ（期待値つき）
docs/PUBLISHING.md    公開の現状、スマートフォンからの公開手順、公開後の確認チェックリスト
SKILL.md              Claude Code に設計・計算・テスト・改善を依頼するための手順
.nojekyll             GitHub Pages で Jekyll 処理を無効化
.github/workflows/test.yml  push / PR 時に単体テストを実行
```

設計方針は次のとおりです。

- **計算と画面を分離しています。** 計算式はすべて `calc.js` の純粋関数にまとめてあります。そのため、Node.js からブラウザなしでテストできます。
- 処理の流れは「生入力（文字列）→ `validate()` → `compute()` → `buildChecklist()` / `buildCsv()`」の一方向です。
- 入力に1つでもエラーがあると `compute()` を実行しません。結果欄は「—」になり、CSV 出力は無効になります。不完全な結果を確定値のように表示しないためです。
- 入力のたびに即時に再計算します。
- `index.html` の Content-Security-Policy で外部通信を禁止しています（`connect-src 'none'`、`form-action 'none'`）。外部フォント・CDN も使いません。

## 2. 計算式と前提条件

### 2.1 入力の単位

| 区分 | 入力の単位 |
|---|---|
| 製造数量 | 1ロットで製造する個数。製造原価の配賦数量として使います |
| 材料 | **1ロットあたり**の使用量と、入力した単位あたりの単価（g 単位なら 円/g） |
| 包装資材 | **商品1個あたり**の数量と単価 |
| 人件費・製造経費 | **1ロットあたり**の金額・時間 |
| 販売関連費用 | **商品1個あたり**（手数料は率） |
| 期間固定費 | 1か月など、利用者が決めた期間の総額 |

### 2.2 製造原価（粗利の計算に使用）

```
材料の投入量            = 使用量 ÷ (1 − ロス率)
材料費（ロット）         = Σ 投入量 × 単価
包装資材費（1個）        = Σ 1個あたり数量 × 単価
包装資材費（ロット）      = 包装資材費（1個）× 製造数量
製造人件費（ロット）      = 製造作業時間 × 1時間あたり人件費
製造経費（ロット）        = 変動製造経費 + 固定製造経費（配賦額）
製造原価（ロット）        = 材料費 + 包装資材費 + 製造人件費 + 製造経費
1個あたり製造原価        = 製造原価（ロット）÷ 製造数量
粗利（1個）             = 税抜販売価格 − 1個あたり製造原価
粗利率                  = 粗利 ÷ 税抜販売価格
```

**ロス率の扱い（良品率で割る方式）**

使用量には、製品に残る「良品として必要な正味量」を入力します。ロスを見込んだ投入量を「使用量 ÷ 良品率」で求めます。

- 例：使用量 1,000g、ロス率 20% → 投入量 1,250g（ロス 250g）
- 「1,000g × 1.2 = 1,200g」のように材料費をロス率分だけ増額する方式とは異なります。この方式は使っていません。
- ロス率は 0% 以上 100% 未満です（100% では投入量が無限大になるため）。

### 2.3 限界利益（販売関連費用を含む変動費ベース）

```
販売手数料（1個）        = 手数料の計算対象額 × 手数料率
  計算対象額 = 税抜販売価格（初期値）
            または 税抜販売価格 × (1 + 消費税率)（「税込販売価格」を選んだ場合）
販売関連変動費（1個）     = 販売手数料 + 送料負担額 + その他の販売関連変動費
変動製造原価（1個）       = 材料費 + 包装資材費 + 変動製造経費
                         + 製造人件費（「変動費」区分の場合のみ）   … いずれも1個あたり
変動費合計（1個）         = 変動製造原価 + 販売関連変動費
限界利益（1個）           = 税抜販売価格 − 変動費合計
限界利益率               = 限界利益 ÷ 税抜販売価格
```

- 粗利と限界利益は別の指標として扱います。
  - 粗利は製造原価（固定費の配賦分を含む）だけを差し引きます。販売関連費用は差し引きません。
  - 限界利益は変動費だけを差し引きます。販売関連費用もここで差し引きます。
- 人件費は画面で「変動費（時給など）」か「固定費（月給など）」を選べます。どちらを選んでも製造原価と粗利は同じです。区分によって変わるのは限界利益だけです。
- 固定製造経費（配賦額）は、粗利の計算では製造原価に含めます。限界利益の計算からは除きます。

### 2.4 損益分岐点

```
損益分岐点販売数量 = 期間固定費 ÷ 1個あたり限界利益   （1個未満は切り上げ）
損益分岐点売上高   = 損益分岐点販売数量 × 税抜販売価格
```

- 期間固定費が**空欄**のときは損益分岐点を計算しません（未入力として扱います）。**0** を入力したときは 0 個になります。
- 限界利益が **0 以下**のときは損益分岐点を計算せず、警告を表示します。
- 期間固定費には、固定費に区分した人件費・製造経費の**期間総額**も含めてください。ロット単位の固定製造経費（配賦額）とは自動では連動しません。期間あたり何ロット作るかは製品によって違うためです。
- 切り上げのときは、浮動小数点誤差（例：100.0000000001）で1個多くならないよう、許容誤差を差し引いてから切り上げます。

### 2.5 価格比較シミュレーション

比較価格は最大5件まで入力でき、それぞれについて上記と同じ式で計算します。

- 製造原価は価格に関係なく同じです。
- 販売手数料は価格に連動するため、価格ごとに再計算します。送料とその他の販売関連変動費は価格にかかわらず同じ額です。
- 「現在比」の差額は、比較価格の値から現在価格の値を引いたものです。
- 価格の推奨や自動決定はしません。

### 2.6 端数処理

| 対象 | 表示・CSV の桁 |
|---|---|
| 内部計算 | 丸めない（倍精度浮動小数点） |
| 1個あたり金額 | 小数第2位で四捨五入 |
| ロット合計・期間金額・損益分岐点売上高 | 円単位で四捨五入 |
| 率（%） | 小数第1位で四捨五入 |
| 損益分岐点販売数量 | 整数に切り上げ |

- CSV にも画面と同じ桁で出力するため、両者の値は一致します。
- 表示上の内訳を合計すると、丸めの影響で合計欄と 0.01 円程度ずれることがあります。

### 2.7 入力検証

| 状況 | 扱い |
|---|---|
| 必須項目（商品名・製造数量・税抜販売価格・材料と包装資材の使用量／数量と単価）が空欄 | エラー |
| 数値以外の文字、`1e5` などの指数表記、`Infinity` | エラー |
| 負の値 | エラー |
| 製造数量 0・小数 | エラー（0除算防止、整数のみ） |
| 販売価格 0 | エラー（粗利率の0除算防止） |
| ロス率・手数料率 100% 以上 | エラー |
| 極端な値（金額 10億円超、数量 1,000万超、作業時間 10万時間超） | エラー |
| 全角数字（１２００）、桁区切りカンマ（1,200） | 受け付けて数値に変換 |
| 任意項目の空欄 | 0 として計算（期間固定費だけは「未入力」として扱う） |
| 材料・包装資材で、単位以外がすべて空欄の行 | 計算から除外 |

### 2.8 注意点・改善チェックリスト

入力条件に応じて、確認事項を「要対応／注意／確認」の3段階で表示します。

- ロス率・包装資材費の割合・粗利率の注意基準は、画面の「H. 注意表示の基準」で変更できます。
- 初期値（ロス率 10%、包装資材費 30%、粗利率 30%）は**このツールの仮の初期設定です。業界標準値や推奨値ではありません。**
- 改善率や業界平均値は表示しません。

## 3. 仮定（仕様が明示されていなかった点）

| 項目 | このツールでの仮定 |
|---|---|
| 材料の使用量 | ロット全体の良品の正味量として扱う |
| 包装資材の数量 | 1個あたりで入力する |
| 販売手数料の計算対象 | 初期値は税抜販売価格。税込も選択でき、その場合は消費税率を必須にする |
| 送料負担額・その他販売費 | 1個あたりの定額とし、価格比較でも一定とする |
| 販売先（直販・卸売・その他） | 記録用。計算には影響しない（チャネル別の手数料率などは自動設定しない） |
| 期間固定費 | ロット単位の固定製造経費とは独立した入力とする（2.4 参照） |
| 消費税 | 販売価格・原価はすべて税抜で扱う。消費税は手数料の計算対象を税込にしたときだけ使う |

## 4. 使い方

1. `index.html` をブラウザで開くか、GitHub Pages の URL にアクセスします。初期状態で架空のサンプルデータが入っています。
2. A〜F に自社の値を入力します。入力のたびに右側（スマートフォンでは下）の計算結果が更新されます。
3. G に比較したい販売価格を入力すると、現在の価格と並べて比較できます。
4. 「CSVを出力」で結果をダウンロードします（UTF-8 BOM 付き、CRLF 改行）。
5. ページを閉じたり再読み込みしたりすると、入力内容は消えます。必要な結果は CSV で保存してください。

サンプルデータの内容と期待値は [docs/EXAMPLES.md](docs/EXAMPLES.md) にあります。

### CSV の仕様

- ファイル名は `maker-margin-studio_YYYYMMDD-HHMM.csv` です。ASCII 文字だけにしています。日本語を含むファイル名にすると、拡張子のない `download` という名前に置き換えるブラウザがあることを確認したためです。商品名は CSV の中に出力します。
- 列は「区分, 項目, 値, 単位, 備考」です。全セルを `"` で囲み、`"` は `""` にエスケープします。
- 先頭が `= + - @ タブ 改行` および全角の `＝ ＋ － ＠` の文字列は、数式として解釈されないよう先頭に `'` を付けます。対象は商品名などの文字列です。数値（負数を含む）はそのまま出力します。
- 出力する内容：
  - 商品情報
  - 材料・包装資材の明細
  - 原価内訳（ロット・1個あたり、変動／固定の区分）
  - 粗利・粗利率
  - 販売関連費用・限界利益
  - 損益分岐点
  - 価格比較
  - 前提条件（ロス率の方式・人件費区分・手数料の計算対象・端数処理）

## 6. GitHub Pages で公開する手順

ビルドは不要です。リポジトリのルートをそのまま公開します。

- スマートフォンからの画面ごとの手順と、公開後の確認チェックリストは [docs/PUBLISHING.md](docs/PUBLISHING.md) にまとめています。
- GitHub Free プランでは、Pages を使うためにリポジトリを Public にする必要があります（有料プランなら Private のままでも使えます）。

1. 公開するファイルが `main` ブランチに入っていることを確認します。
2. GitHub のリポジトリ画面で **Settings → Pages** を開きます。
3. **Build and deployment → Source** で **Deploy from a branch** を選びます。
4. **Branch** で `main`、フォルダは `/ (root)` を選び、**Save** を押します。
5. 数分後、同じ画面に `https://<ユーザー名>.github.io/<リポジトリ名>/` が表示されます。アクセスして動作を確認してください。
6. 更新するときは、`main` に push すると自動で再公開されます。

補足：

- `.nojekyll` を置いて Jekyll の処理を無効にしています。
- 無料プランで GitHub Pages を使うには、リポジトリを public にする必要があります。private リポジトリで公開するには有料プランが必要です。
- 公開後の確認項目：
  - サンプルの計算結果が [docs/EXAMPLES.md](docs/EXAMPLES.md) の期待値と一致する
  - ブラウザの開発者ツールのネットワークタブで、外部ドメインへの通信がない
  - CSV がダウンロードできる

## 7. 制約と今後の拡張候補

- 入力の保存・読み込みの機能はありません。自動保存しないという要件に従っています。
- 1商品ずつの試算です。複数商品の一括比較やセット商品の原価計算には対応していません。
- 次の機能は今後の拡張候補です。
  - 入力内容を JSON ファイルに明示的に保存し、読み込む機能
  - 販売先ごとの手数料プリセット（利用者が自分で登録するもの）
  - 期間あたりのロット数から固定製造経費を配賦する機能
